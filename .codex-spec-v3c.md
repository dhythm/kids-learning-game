# Codex spec: kids-learning-game v3 part C — 漢字ドリルに例文追加

Repo: ~/workspace/proj-kids-learning-game (Vite+React+TS; v3 parts A/B done). Add example sentences to the kanji drill. Do NOT commit/push, do NOT run npm install. You may run `npm test`, `npm run typecheck`, `npm run build`. All existing tests must keep passing (extend the kanji data test). No network, no external data — sentences are self-authored.

## 1. Data: add `example` to every kanji entry
Files: src/data/kanji-grade1.json (80), kanji-grade2.json (160), kanji-grade3.json (200) — 440 entries total.
- Add a field `example` to EVERY entry: one short, natural Japanese sentence (roughly 8–20 characters plus punctuation) that uses the entry's `word` exactly as written (the word string must appear verbatim in the sentence).
- Sentences must be appropriate for elementary school children: everyday topics (school, family, nature, food, play), no scary/violent/adult content, no proper names of real people/brands.
- Use kanji appropriate to the grade level in the rest of the sentence where reasonable (hiragana is fine and often better for young kids — prefer readability: for grade 1, mostly hiragana besides the target word; grades 2–3 may use kanji from their own or earlier grades).
- Keep all existing fields unchanged (kanji, reading, word, wordReading).

## 2. Types + display
- lib/kanji.ts: KanjiEntry gains `example: string`.
- KanjiDrillScreen: after the learner answers (during the feedback phase, alongside せいかい！/おしい！), show the example sentence in a small speech-bubble style block: `例文： <sentence>` with the target word emphasised (e.g. <strong> around the word occurrence — implement by splitting the sentence on the word). Do not show it before answering (it can stay hidden so it doesn't clutter the question; showing it only as feedback is the point).
- Review mode: kanji review questions may also show the example during feedback if the data is handy (ReviewQuestion for kanji gains optional `example` + `word` highlight info) — implement if it fits the existing shape cleanly; if it complicates the review screen, skip review and note it in your summary.

## 3. Tests
- Extend the kanji data test: every entry has a non-empty `example`, the example contains the entry's `word` verbatim, length between 5 and 40 characters.
- App/kanji smoke: after answering a kanji question, the example sentence block （例文） becomes visible.

## Acceptance
`npm test` (all), `npm run typecheck`, `npm run build` pass. No other behaviour changes. README: extend the kanji line with 「例文つき」 if natural.
